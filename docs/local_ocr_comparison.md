# 로컬 OCR 전환/병행 검토 보고 (승인 대기)

> 요청: "AWS가 아닌 LOCAL OCR을 사용하는 방안을 검토하고 성능/기능/정확성/완성도 차이를 비교. 결과 보고 후 최종 승인 시 진행."
> **구현 완료** — 사용자 결정에 따라 AWS Textract / 패턴 학습(로컬) / ONNX RapidOCR(로컬) 3택으로 구현됨 (설정 → OCR 설정 → OCR 엔진). 아래는 결정 당시의 비교 기록.

## 후보 비교

## 권고안 (선택지)

**A. Windows OCR 병행 (권장)** — 설정에 "OCR 엔진: AWS Textract / Windows(로컬) / 로컬 우선+AWS 보완" 3택 추가.
- 근거: 단일 exe 배포 목표를 해치지 않는 유일한 무료 로컬 엔진(OS 내장). 속도는 오히려 빠르고 비용 0.
- "로컬 우선+AWS 보완" 모드: 로컬 결과로 검사하고, 필드 카운트가 기준 미달인 페이지만 Textract 재시도 → **비용 90%+ 절감**하면서 정확도 유지.
- 리스크: 흐린 인쇄·저대비에서 Textract 대비 인식 저하 가능 → 이미 넣어둔 대비 보정 + 혼동 문자 매칭 + 교정 학습이 완충.

**B. Textract 유지 (변경 없음)** — 페이지당 비용이 월 수천 페이지 수준이면 유지 부담이 작음. 오프라인 요구가 없다면 합리적.

**C. Tesseract/Paddle 동봉** — 완전 오프라인 + OS 버전 무관이 필요할 때만. exe 크기 증가와 인식 튜닝 공수를 수반하므로 A로 부족할 때 2차 검토 권장.

## 승인 요청

- [ ] **A안 진행** (Windows OCR 병행 + 로컬 우선/AWS 보완 모드) ← 권장
- [ ] B안 (현행 유지)
- [ ] C안 검토 계속

승인 주시면 A안 기준 구현: OCR 엔진 선택 설정, `IOcrEngine` 추상화, WindowsOcrEngine(net8.0-windows `Windows.Media.Ocr`), 로컬 우선 폴백 파이프라인, 페이지 캐시 키에 엔진 식별자 반영, 실측 정확도 비교 리포트(같은 PDF를 두 엔진으로 돌려 필드 카운트 diff) 기능 포함.
