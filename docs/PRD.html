1. 개요

1.1 배경

의료기기 라벨은 인쇄 시트 단위(PDF)로 출력되며, 한 페이지에 같은 LOT의 라벨이 여러 장(예: 11~13장) 배치된다. 출하 전 검사자는 각 라벨에 인쇄된 LOT·품번(PN)·REF·제조일·유효기간·GTIN이 주문 목록과 일치하는지, 그리고 바코드(GS1-128·DataMatrix)가 올바른 값을 담고 있는지 확인해야 한다. 종래 방식의 문제는 네 가지다.

  • 수작업 대조의 누락. 페이지당 수십 개의 텍스트 필드를 눈으로 대조하다 보면 한 장의 오기(誤記)를 놓치기 쉽고, 누락은 회수·규제 지적으로 이어진다.
  • 두 개의 분리된 도구. 검사 목록을 만드는 프로그램(엑셀 3종 병합)과 라벨을 검사하는 프로그램이 분리되어 있어 목록 파일을 옮기고 규격을 다시 고르는 이중 작업이 있었다.
  • OCR 오인식 처리의 부재. 라벨 폰트·인쇄 품질에 따른 O↔0, I↔1 같은 혼동을 매번 사람이 걸러야 했고, 같은 오인식이 반복돼도 프로그램은 학습하지 못했다.
  • 기록의 부재. 검사 결과가 화면에만 남고 이미지·이력·CSV로 남지 않아 사후 추적이 어려웠다.

LaVIS는 목록 생성 → 라벨 OCR·바코드 검사 → 판정·기록을 하나의 앱으로 통합하고, 검사자가 확인해야 할 곳만 빠르게 드러내는 것을 목표로 한다.

1.2 목표

  1. PDF를 열면 전 페이지가 백그라운드에서 OCR·바코드 분석되고, 페이지를 넘길 때 기다림 없이 판정이 표시된다 (선행 프리페치 + 캐시, 재과금 없음).
  2. 페이지의 LOT을 라벨에서 읽어 목록과 자동으로 맞추고, 라벨에 인쇄된 양식 문서번호(예: Rev.A00, BSL-01, PML-001 + Rev.1)로 검사 규격을 자동 선택한다. 사람이 고른 값은 항상 자동보다 우선한다.
  3. 필드별 기대 출현 횟수(규격 정의)와 실제 검출 수를 비교하고, GS1-128 바코드의 GTIN·LOT·유효기간을 목록과 교차 검증해 '합격 / 확인 필요'를 낸다. 거짓 합격을 만들 수 있는 상황(LOT 미매칭, GS1 해석 불가, GTIN 추출 실패)은 반드시 '확인 필요' 또는 오류로 드러낸다.
  4. 검사자가 확인해야 할 곳(미검출·저신뢰·불일치)이 화면·모아보기 표·결과 목록·저장 이미지에서 같은 색·같은 문구로 보인다.
  5. OCR 오인식·단어 분리·필드 위치·문서번호 규칙을 사용자가 프로그램 안에서 등록·교정할 수 있고 (커스터마이징), 그 데이터는 프리셋으로 다른 PC에 옮길 수 있다.
  6. 전 페이지 자동 검사 → 부적합 로트만 모아 보기 → 문제 해결 → 검사자 확인 합격 처리의 흐름이 한 화면에서 끝나며, 결과는 이미지·SQLite 이력·CSV로 남는다.
  7. 판정은 검사자가 내린다. 프로그램의 '확인 필요'는 불합격이 아니라 검사자 확인 대기이며, 검사자 확인 합격은 사유와 함께 기록된다.

1.3 용어

용어정의
검사 목록시트 Label Inspection List, 열 LOT, PRODUCTS, PN, REF, MFG DATE, EXP DATE, GTIN. 목록 생성 탭이 만들거나 xlsx로 연다
레코드검사 목록의 한 행(한 LOT). 페이지 검사의 기대값 원천
규격(Standard)standards.json의 항목. 필드별 기대 출현 횟수(counts)·날짜 표기(date_format)·표시명(display_name)·문서번호 패턴(doc_patterns)
문서번호라벨에 인쇄된 양식 번호·개정 (PML-001 / Rev.1, BSL-01(Rev.5), Rev.A00). 규격 자동 선택의 유일한 근거
필드검출 대상 항목. 기본 LOT / PN / REF / MFG DATE / EXP DATE / GTIN (+중국 규격은 CHINA, +커스텀 필드). PRODUCTS는 규격이 기대 횟수를 명시할 때만
검출 수 / 기대 수페이지에서 필드 값이 검출된 횟수 / 규격이 요구하는 횟수. GTIN은 규격과 무관하게 기대 1(1개 이상 일치면 합격)
합격 / 확인 필요자동 판정. 모든 게이트 필드 검출 수 = 기대 수 ∧ 모든 바코드 교차검증 일치 → 합격, 아니면 확인 필요
검사자 확인 합격자동 '확인 필요' 페이지를 검사자가 육안 확인 후 사유와 함께 합격으로 확정한 최종 판정. 자동 판정은 보존
바코드 검증 표우측 하단 표. GS1-128 등 1D GS1 바코드의 AI 값과 레코드 대조 결과. DataMatrix는 표시하지 않음
DataMatrix 정책화면·저장 이미지에 청록 박스로 위치만 표시. 카운트·검증·GTIN 원천에서 제외
GSGroup Separator(0x1D, FNC1). 가변 길이 AI 값의 종료 구분자
영역(Zone)필드 검출을 인정할 페이지 비율 사각형. 드래그·클릭으로 등록, 규격별 또는 전체
교정(Correction)OCR 오인식 치환 사전 (예: 2S090776→25090776). 필드 더블클릭·OCR 로그에서 등록
병합(Merge)여러 OCR 단어를 한 문장으로 합치는 학습 규칙 (예: 2024- + 05-10)
프리셋.lavispreset — 규격·필드 규칙·영역·양식 감지·컬럼 매핑·학습 데이터 묶음
자동 학습검사 중 조용히 데이터가 쌓이는 4개 모듈(OCR 패턴·라벨 유형·동일값 배치·기준정보 DB). 기본 모두 꺼짐
페이지 슬롯툴바 아래 페이지 상태 띠. 회색=OCR 대기 / 흰=검사 대기 / 녹 ✓=합격 / 주황 !=확인 필요 / ?=LOT 미매칭 / 굵은 초록=검사자 확인 합격

3. 제품 범위

3.1 포함 (In Scope)

  • 검사 목록 생성: 주문일정·품목번호·BSC 엑셀 3종 → 날짜 선택 → 목록(xlsx) 생성·저장·검사 탭 전달
  • 라벨 PDF 검사: 렌더 → 라벨 정렬 → OCR(3엔진) + 바코드 검출 → LOT 매칭 → 규격 선택 → 필드 카운트 · GS1 교차 검증 · 기준정보 대조 · 동일값 패턴 → 합격/확인 필요 → 오버레이 표시
  • 검사 보조 UI: 필드 모아보기 표, 페이지 슬롯, 다음 확인 대상 이동, OCR 인식 로그, 미검출 진단, 바코드 인식 모드(클릭 판독)
  • 커스터마이징: 규격 기대 횟수·표시명·문서번호 패턴, 필드 제외·커스텀 필드(정규식)·영역·문자 제약· 동일값 패턴·양식 감지 규칙, 교정·병합 학습, 색상·오버레이, OCR 엔진/임계, 저장 옵션, 프리셋 이식
  • 전 페이지 자동 검사, 결과 목록(부적합만 보기), 검사자 확인 합격 처리(사유 필수)
  • 기록: 주석 JPEG 저장(요약 박스), SQLite 검사 이력, 페이지 전체 CSV(검사자 처리 열 포함), LOT별 리포트 xlsx, 기준정보(마스터) DB
  • 설정 안전장치: 원자적 저장, 스키마 이전, 범위 밖 값 자동 보정·안내, 손상 파일 복구, 프리셋 가져오기 전 자동 백업
  • 빌드 식별: CI가 주입한 정보 버전(태그 또는 sha7)을 About 오버레이·상태바·이력 app_version에 표시, 배포 zip에 SHA-256

3.2 제외 (Out of Scope)

  • 전자서명·감사추적·사용자 로그인 (21 CFR Part 11 대상 시스템 아님 — §15)
  • 라벨 디자인 검토(레이아웃·폰트·색상 규격 적합성), 인쇄 색차 측정
  • ISO/IEC 15415 정식 바코드 검증 (손상 등급은 간이 근사, 참고용)
  • 스캐너·카메라 실시간 입력 (PDF 파일 입력만; 실물 스캔 검사는 UDInspect 영역)
  • 검사 성적서 PDF 출력 (C-02, 미결 — §17)
  • 자동 판정만으로 출하 가부를 결정하는 워크플로

3.3 사용 시나리오

S1. 일일 출하검사 (표준 흐름)

  1. 목록 생성 탭: 주문일정·품목번호·(일본 건이 있으면) BSC 파일 선택 → 제조일 체크 → [리스트 생성] → 경고 확인 → [검사 탭으로 보내기].
  2. 검사 탭: [PDF 열기](또는 끌어놓기) → 전 페이지 OCR이 백그라운드로 진행(상태바 진행 막대).
  3. [▶ 자동 검사] → 완료 시 결과 목록 창이 '부적합만 보기'로 열림.
  4. 부적합 행 더블클릭 → 페이지 이동 → 모아보기 표·붉은/주황 칸으로 원인 확인 → LOT 수동 선택, 교정 등록, 영역 등록 등으로 해결 → F5 재검사.
  5. 여전히 '확인 필요'지만 육안으로 정상이면 [합격 처리 (검사자 확인)…] → 사유 입력.
  6. 자동 저장(또는 [결과 저장]) → 주석 이미지·이력 → [CSV 내보내기]로 페이지 전체 기록.

S2. 신제품군 첫 검사 (커스터마이징)

  1. 설정 › 규격·양식 감지에서 규격 기대 횟수 수정, 필요 시 standards.json에 표시명·doc_patterns 추가.
  2. 첫 페이지에서 미검출 필드 더블클릭 → 진단 → OCR 로그에서 병합/교정 등록.
  3. 필드가 엉뚱한 곳에서 잡히면 [✚ 필드 영역 등록]으로 위치 제한.
  4. 안정되면 [프리셋 내보내기]로 다른 검사 PC에 배포.

S3. 바코드만 확인

  • [▣ 바코드 인식] → 라벨 위 DataMatrix/GS1-128 클릭 → 판독값·GS1 요소·목록 대조 확인 → [값 복사].

14. 오류·예외 처리 원칙

  • 거짓 합격을 만들 수 있는 모든 결손은 '확인 필요' 또는 오류로 드러낸다: LOT 미매칭, GS1 해석 불가, GTIN 추출 실패, 바코드 값 불일치.
  • 정보성 알림은 상태바, 결정이 필요한 것만 대화상자(기본 '아니오'). 같은 원인의 팝업 연쇄 금지.
  • 파일 오류(잠김·권한·디스크·네트워크)는 원인별 문구로 안내하고 검사 결과는 유지한다.
  • 백그라운드 예외는 crash.log, 설정 폴백·검사자 처리는 app.log에 남긴다.

15. 규제상 위치

LaVIS는 검사 보조 도구다. 프로그램은 검출 결과와 참고 판정('합격' / '확인 필요')을 표시하고, 최종 합격·불합격은 검사자가 결정한다. '확인 필요'는 불합격이 아니라 검사자 확인 대기다. 검사자 확인 합격은 사유·처리자·시각과 함께 기록되지만 전자서명이 아니며, 전자서명·감사추적(21 CFR Part 11) 대상 시스템이 아니다. 자매 제품 UDInspect와 같은 간이 검증 트랙(위험 낮음, GAMP 범주에서 구성 가능한 도구)을 전제로 하며, 도구 식별(빌드 버전·SHA-256)·자동 테스트·실기 체크리스트가 검증 근거를 이룬다.

16. 알려진 제한사항

  • OCR 정확도는 엔진·인쇄 품질에 좌우된다. AWS Textract 외 로컬 엔진은 폰트 학습 정도에 따라 재현율이 낮을 수 있다.
  • 문서번호가 인쇄되지 않은 라벨(중국 규격 등)은 규격 자동 선택이 되지 않아 이전 규격 유지·수동 지정에 의존한다.
  • DataMatrix는 정책상 검증하지 않는다. DataMatrix 값 확인은 바코드 인식 모드(클릭)로 한다.
  • 바코드 손상 등급은 교정 장비의 성적서를 대체하지 않는다.
  • 라벨 정렬은 하늘색 이형지 배경을 전제로 한다. 배경이 다르면 크롭이 생략되고 기울기 보정만 시도된다.
  • 자동 검사는 OCR 완료를 기다리므로 총 소요 시간은 OCR 엔진 속도에 좌우된다(페이지당 수 초).
  • 검사자 확인 합격은 페이지 단위이며 라벨(객체) 단위 부분 판정은 없다.
